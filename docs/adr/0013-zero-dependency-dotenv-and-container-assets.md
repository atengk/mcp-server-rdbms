# 0013: 零第三方依赖本地 Dotenv 探测与生产级容器资产

## 背景与痛点

1. **本地调试与容器环境的摩擦**：本地离线开发与自动化脚本调试中，开发者习惯在当前目录放置 `.env` 文件快速注入数据库连接凭证。传统方案通常引入外部依赖库 `python-dotenv`，但这会增加打包体积与潜在依赖冲突；
2. **私有云与私有化部署缺乏官方资产**：除客户端本地 stdio 模式拉起外，大量团队需在私有 NAS、Docker 或 Kubernetes 中以后台常驻 SSE 协议提供网络服务，缺乏官方生产级容器定义。

## 架构决策

1. **轻量零依赖 `.env` 自适应加载器 (`load_dotenv_if_exists`)**：
   - 纯 Python 标准库实现，逐行解析标准 KEY=VALUE 与单双引号包裹值；
   - 遵循“系统已有环境变量绝不覆盖”的防御性优先契约，仅填充系统缺失的键；
   - 仅在本地存在 `.env` 文件且未显式传入外部 env 字典时无感自适应激活。
2. **生产级容器资产矩阵**：
   - 提供基于 Python 3.12 官方 slim 镜像的多阶段极速 `Dockerfile`，集成 `uv` 极速包管理器并内置常用数据库驱动；
   - 默认注入 `MCP_RDBMS_TRANSPORT=sse`、`0.0.0.0:8000`，达成 100% 容器无参启动；
   - 提供开箱即用的 `docker-compose.yaml` 模板，支持挂载 `connections.yaml` 或直接通过环境变量注入连接凭证。

## 收益与结果

- 保持项目“依赖克制与高内聚”底线，零新增第三方运行期依赖；
- 补齐了容器化交付生态，为后续自动化推送到 GHCR 奠定扎实基础。
