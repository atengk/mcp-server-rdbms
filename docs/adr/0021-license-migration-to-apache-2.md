# 0021: 全面迁移至 Apache License 2.0 开源协议与版权脱敏

- **状态**: Accepted
- **日期**: 2026-10-14
- **决定者**: 阿腾 (Ateng)

## 背景与痛点

本项目自早期研发阶段起，根目录采用了简明短小的 MIT License。但随着项目逐步集成现代开源工程规范（对齐模版仓库 [`atengk/oss-template`](https://github.com/atengk/oss-template)）并迈入稳定分发期，原有的协议配置暴露出以下法律与工程管理痛点：

1. **缺乏显式专利授权与防卫条款 (Patent Retaliation Clause)**：MIT 协议虽然高度宽松，但未显式界定专利授权边界。当下游商业组织采用本项目或提交衍生代码时，原作者与采用者缺乏专利诉讼互防保障；
2. **缺乏商标保护声明**：MIT 未明确排除商标权限，无法严格防范第三方在分发衍生品时滥用项目商标与品牌标识；
3. **衍生品强制归属与审计凭证缺失**：随着 Docker 多架构镜像（GHCR）与 PyPI 预编译制品的自动化分发，需引入标准 `NOTICE` 文件以确立作品原初归属；
4. **隐私与版权署名脱敏需求**：历史文档与元数据中存在个人真实姓名，需根据开源社区最佳实践统一脱敏为专用开源代号（中文：阿腾，英文：Ateng）。

## 架构与法律决策

经全面推演与决策，决定将本项目开源许可证正式由 **MIT License** 迁移为 **Apache License 2.0**，并完成全链路元数据与署名对齐：

1. **核心许可证与 NOTICE 确立**：
   - 根目录采用标准 Apache License 2.0 全文；
   - 新增根目录 `NOTICE` 文件，声明项目原初著作权归属 `阿腾 (Ateng)`，确保第三方在任何重新分发或二次封装衍生品中依法保留版权归属声明；
2. **多生态元数据无缝对齐**：
   - `pyproject.toml`：将 `license` 字段更新为 `{ text = "Apache-2.0" }`，并在 `classifiers` 中引入 `"License :: OSI Approved :: Apache Software License"`；
   - `pyproject.toml`：作者信息标准化更新为 `阿腾 (Ateng)`；
   - `README.md`：同步更新顶部 License 徽章（`License-Apache_2.0-blue.svg`）及文末治理矩阵中的开源许可表述；
3. **全局真实姓名彻底脱敏**：
   - 全局扫描代码库，对历史 ADR（ADR-0015、ADR-0016、ADR-0017）及配置中的个人真实姓名进行 100% 替换脱敏，统一采用“阿腾 (Ateng)”。

## 后续影响与收益

- **商业友好且法律严谨**：下游企业与个人开发者可在完全遵循商业友好的前提下放心集成，同时原作者与贡献者享有明确的专利互防保护；
- **全域一致性**：PyPI 索引、GitHub 徽章、Docker 镜像元数据与仓库根目录协议完全闭环吻合，消除了包管理器与开源合规审查工具的歧义告警。
