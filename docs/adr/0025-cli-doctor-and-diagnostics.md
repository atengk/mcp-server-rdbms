# 0025: 命令行运维诊断器、版本反射与场景化增强体系

- **状态**: Accepted
- **日期**: 2026-10-14
- **决定者**: 阿腾 (Ateng)

## 背景与痛点

随着 `mcp-server-rdbms` 逐步进入生产部署与自动化运维阶段，使用者与运维人员在命令行接入阶段面临四项关键体验与可靠性挑战：

1. **驱动就绪度不可见**：通用数据库服务支持 9 大方言，但各类数据库驱动（如 `psycopg`, `pymysql`, `oracledb`, `pyodbc` 等）采用按需可选依赖设计。用户在配置前无法一目了然得知当前环境已就绪哪些驱动、缺失哪些驱动；
2. **环境配置隐蔽排错成本高**：项目实行严格的专属环境命名空间（`MCP_RDBMS_*`），严禁通用无前缀变量（如 `DATABASE_URL`）以防御跨进程串库。但在实际使用中，开发者可能误设了通用变量或配错了 URL 语法，服务启动后直接静默忽略或在深层调用时才报错，缺乏前置体检；
3. **真实连通性缺乏快速探活通道**：在服务正式以 `stdio` 挂载至 MCP 宿主（如 Claude Desktop / Cherry Studio）前，用户难以通过轻量探针测试网络握手、连通性与账号权限；
4. **命令行自解释性不足**：原生 `--help` 缺乏典型场景端到端命令范例与专属环境变量对照表，且缺失 `--version` 扩展运行时信息与 `--doctor` 自动化健康检查入口。

## 架构决策

经深思推演与 Grilling 决策对齐，决定在客户端 CLI 运维层引入全方位诊断与自解释增强能力：

1. **全面分层自检诊断器 (`core/doctor.py`)**：
   - 严格恪守“精炼 6 核心工具契约”的架构红线：`--doctor` 是客户端 CLI 运维命令，严禁扩散至 MCP 协议层工具；
   - 诊断覆盖四大核心维度：
     - **系统与运行时环境**：Python 版本、操作系统平台架构、SQLAlchemy/SQLGlot 版本及 `.env` 自适应探测状态；
     - **驱动支持矩阵 (Driver Matrix)**：静态排查 9 大主流方言驱动的安装就绪状态，对未就绪驱动输出精准的一键安装指引；
     - **环境命名空间合规审计 (Namespace Hygiene)**：探查系统环境中是否存在被废弃或可能产生歧义的通用变量（如 `DATABASE_URL`），主动提示已被专属命名空间防御机制忽略；审计有效变量与 URL 语法合法性；
     - **连接握手探活探针 (Connection Probe)**：对已配置连接建立短连接探活，执行极简 `SELECT 1` 验证网络通畅度与账号权限，敏感凭据强制脱敏。
2. **双模输出呈现（富文本卡片 + 机器可读 JSON）**：
   - 默认通过 `rich` 渲染美观终端卡片与表格（`[✓]` 就绪 / `[!]` 警告 / `[✗]` 失败）；
   - 支持 `--format json` 输出标准 JSON 报告，便于 CI/CD 自动化健康巡检；
   - 严格的运维退出码语义：无严重故障（允许未用驱动缺失等警告）退出码为 0，存在连通性失败或非法配置时退出码为 1。
3. **运行时扩展版本信息 (`--version`)**：
   - 输出统一规范为：`atengk-mcp-server-rdbms v<version> (Python <py_ver>, SQLAlchemy <sa_ver> on <platform>)`，秒级定位运行基线。
4. **场景化增强帮助体系 (`--help`)**：
   - 定制 `RawDescriptionHelpFormatter` 并在底部 `epilog` 注入一键启动最佳实践范例、专属环境变量对照表与方言驱动安装速查表。

## 效果与收益

- **开箱即用的运维自愈力**：开发者在接入异常时只需运行 `mcp-server-rdbms --doctor` 即可在 1 秒内获知驱动缺失、变量拼写或连接网络阻断的具体根因；
- **CI/CD 友好**：支持机器可读的 JSON 导出与语义化退出码，赋能自动化部署前置冒烟校验；
- **架构纯粹**：将自检探针严格限制在 CLI 边界，坚守核心协议层轻量内聚不变量。
