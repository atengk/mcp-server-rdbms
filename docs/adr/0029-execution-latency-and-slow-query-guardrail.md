# 0029: SQL 执行耗时度量、多库路由回显与慢操作自愈预警体系

- **状态**: Accepted
- **日期**: 2026-11-04
- **决定者**: 阿腾 (Ateng)

## 背景与痛点

在生产级 Agent 数据库交互中，深入排查与推演揭示了数据执行工具（`sql_query`、`sql_dml`、`sql_ddl`）存在的若干关键体验与可观测性缺陷：

1. **核心契约不对称与耗时度量遗漏**：`sql_dml` 与 `sql_ddl` 均已返回 `duration_ms`，而只读查询 `sql_query` 内部虽然已计算耗时并落盘审计日志，但返回给大模型的 `QueryResult` 契约载荷中遗漏了该字段，导致智能体无法直接感知查询响应延迟；
2. **耗时浮点数精度发散**：现有写操作工具直接输出原生高精度浮点数（如 `12.3456789...`），不仅消耗多余 Token，且缺乏统一的度量精度标准；
3. **多库路由缺乏结果回显溯源**：在配置了多个数据库连接实例（Multi-DB Routing）的场景下，返回结果未显式回传当前语句实际执行的目标连接别名（`db`），易引发大模型跨库执行的认知混淆与结果归属幻觉；
4. **慢操作缺乏智能体自愈指引**：服务此前仅在达到超时阈值时熔断中断，对接近超时或长耗时的慢查询缺乏主动诊断指引（如提示启用 `explain=True` 或检查 `WHERE` 索引过滤）；
5. **载荷体积缺乏感知与防爆预警**：只读查询仅具备基于行数上限的截断保护（`truncated`），面对宽表大字段时字符体积仍可能导致上下文溢出；
6. **执行计划全表扫描缺乏启发式提示**：大模型调用 `sql_query(explain=True)` 时仅原样返回方言底层原生输出，缺乏对常见全表扫描特征的即时提炼。

## 架构决策

经 Grilling 架构推演与契约论证，决定在三大核心 SQL 数据执行工具中构建**对称式高阶自愈契约（Symmetric Self-Healing Contract）**：

1. **统一返回契约对称性与精度规约 (Contract Symmetry)**：
   - 在 `QueryResult` 顶层补齐 `duration_ms: float = 0.0`、`db: str = ""`、`data_bytes: int = 0` 与 `warning: str | None = None`；
   - 在 `DmlResult` 与 `DdlResult` 中对齐增加 `db: str = ""` 与 `warning: str | None = None`；
   - 全局执行耗时一律采用 `round(duration_ms, 2)`（保留两位小数毫秒），度量范围涵盖从工具入口分发、AST 语法守卫、线程池异步卸载、数据库网络 I/O 到序列化渲染的端到端全链路开销。
2. **专属环境配置与自适应动态阈值 (Slow Query Guard)**：
   - 遵循专属命名空间引入环境变量 `MCP_RDBMS_SLOW_QUERY_THRESHOLD_MS`（默认 `1000.0` 毫秒）；
   - 在工具执行中根据调用方传入的 `timeout` 参数动态收敛阈值：`effective_threshold = min(configured_threshold, timeout * 1000.0 * 0.5)`，兼顾不同超时场景。
3. **三大智能体自愈诊断预警 (Agent Self-Healing Insights)**：
   - **慢查询预警**：当 `duration_ms >= 动态阈值` 时，在 `warning` 字段注入指引文案，建议传入 `explain=True` 获取执行计划或补充精准索引条件；
   - **大体积预警**：统计序列化数据的近似 UTF-8 字节数，当 `data_bytes >= 65536`（64KB）时提示精简投影字段以避免 `SELECT *`；
   - **全表扫描诊断**：在 `explain=True` 模式下启发式扫描执行计划文本，检测到全表扫描特征（如 SQLite `SCAN <table_name>`、PostgreSQL `Seq Scan`、MySQL `type: ALL` 等）时，主动提示检查索引覆盖情况；
   - **写操作预警**：DML 耗时较长或受影响行数较大（$\ge 1000$ 行）以及 DDL 耗时较长时提供潜在锁表与分批提交建议。

## 效果与收益

- **契约对称一致**：三大核心数据执行工具契约对齐，消除下游客户端与 LLM 的接入理解鸿沟；
- **防串库幻觉**：显式回显目标数据库连接别名，确保复杂多库业务流中数据溯源精准无误；
- **赋能 Agent 自愈**：将传统被动的超时熔断升级为前置的主动智能体指引，大幅提升大模型自主排查慢查询与优化 SQL 交互的成功率；
- **零破坏性向后兼容**：所有新增字段均提供安全默认值，存量客户端完全平滑升级。
