# 0023: 彻底废除无前缀通用环境变量并确立 MCP_RDBMS_* 绝对专属命名空间

- **状态**: Accepted
- **日期**: 2026-10-14
- **决定者**: 阿腾 (Ateng)

## 背景与痛点

在早期设计中，为了兼顾不同开发者的使用习惯，服务在环境变量解析层支持了大量的“宽容兼容变量”（如 `DATABASE_URL`、`HOST`、`PORT`、`DB_USER`、`CONFIG_FILE` 等）。但在真实部署与生产实践中，这种宽容设计引发了严重的架构隐患：

1. **跨进程环境污染与意外串库**：`DATABASE_URL`、`HOST`、`PORT` 属于操作系统宿主机、父级 Shell 及其他技术栈（如 Node.js、Django、Docker 宿主服务等）高度共享的通用标识。当本项目在共享服务器或复杂容器中运行时，宿主预设的全局 `PORT=80` 或 `DATABASE_URL` 会被意外劫持读取，引发端口冲突或错误连接到其他数据库的严重事故；
2. **缺乏单一真实源 (Single Source of Truth)**：同一种配置在环境变量中存在多种可能来源，导致故障排查与日志审计时难以快速定位生效的真实配置项；
3. **文档与认知负荷冗余**：开发者和智能体需理解“推荐变量”与“兼容变量”的双重对照关系，增加了不必要的认知摩擦。

## 架构决策

经全面推演，决定对服务环境变量体系实施**彻底纯净化与单一专属命名空间收敛**：

1. **100% 物理切断无前缀与历史兼容变量**：
   - 彻底废除 `DATABASE_URL`、`HOST`、`PORT`、`DB_*`、`CONFIG_FILE`、`DEFAULT_DB`、`MCP_ALLOW_*` 等所有无完整专属前缀的别名；
   - 环境变量解析器仅识别以 `MCP_RDBMS_*` 开头的标准规范键（如 `MCP_RDBMS_DB_URL`、`MCP_RDBMS_CONFIG`、`MCP_RDBMS_SERVER_PORT`、`MCP_RDBMS_DEFAULT_DB`）；
   - 系统宿主环境中任何通用环境变量均被 100% 物理隔离忽略。
2. **严格全大写格式规范**：
   - 所有环境变量必须遵循全大写 + 下划线规范，消除跨平台（Windows / Linux / macOS）的大小写敏感性歧义。
3. **清晰界定“键隔离”与“值容错”**：
   - 收敛仅作用于**键名 (Key)** 维度；对于布尔类型的值内容（如 `MCP_RDBMS_ALLOW_DML`），依然保持宽容布尔解析（支持 `1/0`, `true/false`, `yes/no`, `on/off`），兼顾脚本调用便利。
4. **全域文档与单测清理**：
   - 清理所有参考文档中的“兼容变量”列；
   - 单元测试新增针对未带专属前缀变量的负向安全测试，确保其绝对不被误读。

## 效果与收益

- **绝对安全隔离**：彻底杜绝同机其他进程环境变量串入引发的事故；
- **配置确定性 100%**：排查问题只需全局检索 `MCP_RDBMS_*`，零歧义；
- **心智负担极大减轻**：配置体系干净、清晰、专业。
