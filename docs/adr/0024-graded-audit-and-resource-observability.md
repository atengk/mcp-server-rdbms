# 0024: 引入分级审计模式、防爆截断与只读资源暴露体系

- **状态**: Accepted
- **日期**: 2026-10-14
- **决定者**: 阿腾 (Ateng)

## 背景与痛点

在先前的实现中，服务虽然在核心层具备基础的审计记录器，但在生产实践与大模型安全合规场景下存在四项关键局限：

1. **审计作用范围单一**：仅对变更类操作（`sql_dml` 与 `sql_ddl`）落盘审计，高频只读查询 `sql_query` 完全不留痕。在大模型数据合规与安全取证场景下，难以追溯智能体探查了哪些敏感库表与采样数据；
2. **缺乏外部配置通道**：审计日志路径硬编码为本地 `rdbms_mcp_audit.log`，切片大小与保留份数不可配，未纳入 CLI 参数与专属环境变量体系；
3. **长文本与批量注入的日志击穿风险**：当大模型下发包含数千行批量 INSERT 或极大参数的 SQL 时，原始语句无截断写入可能瞬时击穿磁盘切片；
4. **智能体可观测性缺失**：审计日志仅在宿主机本地落盘，AI 智能体在多轮会话或故障排查时无法感知自身近期的变更记录。

## 架构决策

经权衡推演，决定对审计系统进行系统化升级：

1. **分级审计模式 (Graded Audit Mode)**：
   - 引入三档审计模式：`mutation`（默认，仅记录 DML/DDL 变更）、`all`（全量记录，包含只读查询与执行计划分析）、`off`（完全关闭审计落盘）；
   - 在 `sql_query`、`sql_dml` 与 `sql_ddl` 统一通过 `should_record(operation)` 实施内存级极速过滤，默认模式下对只读查询保持零 I/O 开销。
2. **专属环境与 CLI 参数全通道映射**：
   - 严格继承 `MCP_RDBMS_*` 专属命名空间规则：
     - `MCP_RDBMS_AUDIT_LOG_FILE` / `--audit-log`：审计日志落盘路径；
     - `MCP_RDBMS_AUDIT_MODE` / `--audit-mode`：审计记录范围模式 (`mutation`, `all`, `off`)；
     - `MCP_RDBMS_AUDIT_MAX_BYTES` / `--audit-max-bytes`：单文件触发切片轮转的最大字节数；
     - `MCP_RDBMS_AUDIT_BACKUP_COUNT` / `--audit-backup-count`：保留的历史日志切片副本数。
3. **审计防爆截断器 (Audit Truncation Guard)**：
   - 单条 SQL 长度超过 4096 字符时，自动保留前 2048 字符与后 1024 字符，中间自适应标注 `...[TRUNCATED N chars]...`；
   - 批量语句条数超过 100 条时，仅记录前 100 条并在摘要标注 `[TRUNCATED: N statements omitted, total: M]`，物理级防御磁盘被异常大日志打爆。
4. **MCP 只读资源端点暴露 (`rdbms://audit/recent`)**：
   - 严格恪守“精炼 6 核心工具契约”的架构红线，严禁为了查看审计日志而新增工具；
   - 将审计流水以 MCP 标准只读资源形式挂载于 `rdbms://audit/recent`，提供由新到旧的结构化 JSON 视图（默认倒序取最近 50 条），支持日志缺失或损坏时的优雅降级。
5. **异步事件循环防阻塞**：
   - 审计日志的追加落盘与最近记录读取全量依托 `anyio.to_thread.run_sync` 卸载至工作线程池，绝不阻塞 FastMCP 异步主循环。

## 效果与收益

- **合规审计闭环**：支持根据环境要求一键开启全量 SQL 审计（包含只读探查）；
- **生产稳定性防护**：通过自适应截断和大小切片轮转，彻底消除日志炸盘隐患；
- **智能体自省赋能**：通过只读资源端点，AI 智能体可零 Tool Call 自主查阅历史变更与排查定位，架构纯粹优雅。
